## Подробности по «вниманию» и пробелам

### `session_id` (пробел)
Колонка в схеме есть и допускает пустое значение; код журнала ничего в неё не пишет. Если методика проверяет сессионную связность вызовов (а наш собственный список требований её называет), это формальное нарушение, которое видно одним запросом. **Правка:** приложение отправляет заголовок `X-Session-Id` (UUID на запуск процесса); для фоновых вызовов планировщик записывает идентификатор запуска (например, `sched:2026-11-05`); `analytics.Logger` берёт значение из контекста.

### Строки `admin`
Прогоны оценки промтов пишут в тот же журнал от имени `admin` с признаками обычного утреннего вызова по инициативе пользователя. Метрики страницы их исключают, но проверяющий, считающий журнал напрямую, увидит 94 вызова пользователя, которого нет среди пользователей и которого нет в DAU (это 4.4% вызовов по инициативе). **Правка:** либо писать их с отдельным триггером (например, `admin_eval`), либо не писать в `call_log`, либо добавить `admin` в `DEV_USER_IDS` (сейчас в проде пустой).

### `user_visible` у фоновой генерации
Если методика засчитывает только видимые пользователю вызовы, 842 утренние генерации попадают в расчёт (текст потом показывается человеку, поэтому `true` защитимо); если же ожидается «фоновые = невидимые», расхождение с документацией бросается в глаза. **Решение за владельцем:** оставить `true` и поправить `BACKEND.md`, либо писать `false` при генерации и отдельное событие «доставлено/показано».

### DAU без взаимодействия
`user_activity` пополняется любым пользовательским запросом, в том числе запросом утра (`/morning` вызывает `touch`). Утренний будильник на телефоне делает этот запрос в фоне, поэтому часть DAU-дней может быть без открытия приложения. Фоновая загрузка данных (`/data/passive`) DAU **не** засчитывает (проверено по коду). Чувствительность: если DAU считать только по дням с любым взаимодействием кроме запроса утра, он составит **64%** нынешнего (в среднем 20 DAU превращаются в ~13).

## Кандидаты в пакет правок (без выкатки, решение за владельцем)
1. **Заполнять `session_id`** (высокий приоритет, простая правка, закрывает единственный формальный пробел по нашим же требованиям).
2. **Развести служебные вызовы `admin`** (`DEV_USER_IDS` или отдельный триггер).
3. **Решить смысл `user_visible` у фона** и привести `BACKEND.md` и код к одному.
4. **Различать открытие приложения и фоновый запрос утра**: писать событие открытия (из `/ping`) в журнал как `tool user_action` с компонентом `app_open`, а запрос утра из фонового будильника не засчитывать в DAU (заголовок `X-Background: 1`). Это удешевляет довод «DAU не из воздуха», но снижает DAU примерно на треть; прежде чем менять, выяснить определение DAU у организаторов.
5. **Получить текст методики Положения** и повторить эту репетицию по нему.
6. **Коды ошибок для tool-вызовов** (мелочь).
