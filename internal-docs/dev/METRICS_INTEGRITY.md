# Metrics Integrity — аудит концентрации LLM-вызовов

**Дата:** 2026-10-13. **Повод:** два аккаунта дают ~30% всех LLM-вызовов — самопроверка на anti-fraud, чтобы объяснение было готово раньше, чем спросят организаторы.

Все цифры — из raw `call_log` / `user_activity` на проде, с исключением dev/mock/admin (`is_dev` OR `id LIKE 'mock%'`, `user_id <> 'admin'`). Снято одним проходом SQL через админский доступ к БД.

---

## Вопрос

На 62 зарегистрированных (54 активировано) два аккаунта формируют ~30% LLM-вызовов, и у них видны «бёрсты» — десятки вызовов за минуту. Это накрутка/тест/баг — или реальная вовлечённость?

## Интерпретация (честная)

**Что установлено:**
- Нормировка снимает версию «короткий всплеск»: 353 за **18 дней** = 19.6/день, аккаунты живут 16–18 дней, не 3.
- Это **не dev-аккаунты**: `is_dev` на актуальных сборках не выставлен, тестовое устройство основателя оффлайн на <0.9.8.
- Это **не дубль-баг**: бёрст состоит из разных компонентов, а не повтора одного.
- Среднее Calls/DAU **чувствительно к китам** (n=62): среднее 3.4 против медианы 2.1.

**Что остаётся косвенным (важная оговорка):**
- Посекундный ритм **согласуется** с живым тапаньем, но сам по себе **не доказывает** человеческую природу вызовов — для доказательства нужна привязка к клиентским событиям (тапы/экраны), которой у нас в серверном `call_log` нет. Формулировать: «поведение согласуется с живым использованием», а не «логами доказано, что это человек».

**Вывод:** это **тонкий глубокий тир (~7 юзеров ≥5/день, из них 5 ≥10/день) поверх широко исследующего ядра с сильным многодневным возвратом.** Не накрутка, не dev, не баг. Нормальная ранняя продуктовая картина. Профиль продукта: **широко, но неглубоко** — люди возвращаются (медиана 6 дней) и пробуют много механик (медиана 4), но за сессию тыкают мало (медиана 2.1).

## Для организаторов (если спросят)

**Аргументы в порядке силы** (сильные — первыми, спорные — не выпячивать):
1. Нормировка на активный день: 19.6 и 17.1 за 16–18 дней — долгоживущие ежедневные юзеры.
2. Многодневный возврат по всей базе: медиана 6 активных дней, 74% на ≥3 дня, 50% на ≥7.
3. Breadth: медиана 4 разных компонента, 75% трогали ≥3 механик.
4. (Косвенно) посекундный ритм бёрста — по запросу, как иллюстрация, без слова «доказано».

**Методология «как считаем»** (нейтрально, для прозрачности):
- dev/mock-аккаунты исключены из всех метрик;
- Calls/DAU = **только LLM-вызовы** (tool-вызовы не считаем — поправлено нами же, было ×7 завышение);
- при n=62 показываем **распределение/медиану**, а не только среднее, т.к. среднее тащат киты.

**Калибровка:** не вешать на публичную страницу защитный баннер «мы не накручиваем» — это привлекает внимание к не-проблеме. Прозрачная методология + этот аудит на запрос разоружают лучше превентивной обороны.

## Воспроизводимость

Аудит пересобирается одним SQL-проходом по `call_log` + `user_activity` (per-user calls/active-day, состав компонентов, посекундные гэпы внутри бёрста, перцентили распределения). Доступ к БД — через админский путь на сервере (`companion`). Данные о реальных именах/контактах/содержимом сообщений не используются — только id, даты, компоненты, таймстемпы.
