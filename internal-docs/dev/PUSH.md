# Push-уведомления (FCM)

## Зачем

Локальный WorkManager не доставляет. Замерено на реальном устройстве 2026-09-27: между
17:36 и 09:39 следующего дня — **16 часов, ноль фоновых запросов**. Ни `DailyCollectWorker`
(раз в 12 ч), ни `WakeWatchWorker` (раз в 15 мин) не отработали ни разу.

Две причины, обе неустранимы на стороне приложения:

- **App Standby Buckets.** Приложение, которое открывают пару раз в день и у которого нет
  пушей, Android опускает в `rare`/`restricted`. Там periodic work идёт раз в сутки в момент,
  который выбирает система.
- **Вендорские убийцы фона.** Xiaomi/MIUI, Honor/EMUI, Samsung, Oppo, Vivo режут WorkManager
  наглухо без ручного добавления в белый список. В РФ это большая часть парка.

Утренний прогноз — это и есть продукт. Его доставка не может зависеть только от телефона.

## Архитектура: гибрид, а не замена

| Слой | Роль |
|---|---|
| `WakeWatchWorker` (локально) | Лучший случай: срабатывает в момент первой разблокировки — сервер этот момент не видит |
| FCM с сервера | Гарантия: доходит, даже когда ОС не даёт приложению работать |

Локальный воркер **оставлен специально**. «Прогноз при первом взятии телефона» — сильная
UX-идея, и чисто серверный пуш её убивает, возвращая к фиксированному времени.

Пуш шлётся с блоком `notification` **и** `data`. С `notification` Android показывает
сообщение из системного трея, даже когда процесс приложения мёртв — ровно тот случай, ради
которого всё это сделано. `data` читает приложение, когда оно живо: по `type=morning` оно
показывает прогноз и ставит отметку «доставлено», чтобы локальный воркер не прислал копию.

## Что нужно настроить (одноразово)

Код готов и работает вхолостую без этих шагов: без `google-services.json` флаг
`BuildConfig.PUSH_ENABLED=false`, без `FCM_CREDENTIALS_FILE` сервер пишет
`push: disabled` и `/admin/push` отвечает 503. Ничего не падает.

### 1. Firebase-проект

1. [console.firebase.google.com](https://console.firebase.google.com) → создать проект
2. Add app → Android → package name **`ru.keegoo.companion`**
3. Скачать `google-services.json` → положить в `android/app/`
4. Этот файл — клиентский конфиг, не секрет; его можно коммитить

Как только файл на месте, Gradle сам подключает плагин (`hasFirebase` в
`android/app/build.gradle.kts`) и `PUSH_ENABLED` становится `true`.

### 2. Service account для сервера

1. Firebase Console → Project settings → Service accounts → Generate new private key
2. Скачается JSON — **это секрет**, в репозиторий не кладём
3. Скопировать на сервер:
   ```
   scp fcm-sa.json root@SERVER:/opt/companion/fcm-sa.json
   ssh root@SERVER 'chmod 600 /opt/companion/fcm-sa.json'
   ```
4. Добавить в `/opt/companion/.env`:
   ```
   FCM_CREDENTIALS_FILE=/opt/companion/fcm-sa.json
   ```
5. `systemctl restart companion` — в логах должно появиться `push: enabled project=…`

OAuth-обмен (подписанный JWT → access token) реализован на stdlib в
`backend/internal/push/fcm.go`. Так сделано намеренно: `golang.org/x/oauth2` требует Go 1.26,
а CI берёт версию тулчейна из `go.mod` — зависимость молча подняла бы весь бэкенд.

## Ручная рассылка

Админ-порт слушает только `127.0.0.1`, Caddy его не проксирует, доступ — через ssh.

```bash
# кого вообще можно достать
bash deploy/push.sh SERVER who

# всегда сначала вхолостую
bash deploy/push.sh SERVER dry "Заголовок" "Текст"

# всем (спросит подтверждение — надо напечатать SEND)
bash deploy/push.sh SERVER all "Заголовок" "Текст"

# одному
bash deploy/push.sh SERVER user u_abc123 "Заголовок" "Текст"

# с типом
TYPE=day_review bash deploy/push.sh SERVER all "Разбор дня готов" "Загляни — посмотрим, как прошёл день."
```

`TYPE`: `morning` | `day_review` | `update` | `custom` (по умолчанию).

Каждая отправка уходит в Telegram-канал разработки. Мёртвые токены (приложение удалили)
определяются по ответу FCM и вычищаются из базы автоматически — в отчёте это поле `dropped`.

## Battery optimization

Запрашивается в онбординге сразу после разрешения на уведомления, пока причина ещё на
экране. Любой ответ пропускает дальше — отказ не блокирует, его страхует пуш.

Разрешение `REQUEST_IGNORE_BATTERY_OPTIMIZATIONS` чувствительно для политик Google Play. Для
нас это нормально: дистрибуция APK-ссылкой, а ежедневное уведомление — не удобство, а само
обещание продукта. При выходе в RuStore проверить их требования.

## Проверка обновлений

`UpdateCheckWorker` — раз в 12 часов спрашивает `/api/v1/version` и, если версия новее,
показывает уведомление один раз на версию (`update_notified_version` в prefs).

Нужно потому, что канал дистрибуции — APK-ссылка: ничего не обновляется само и никто не
узнаёт, что вышел фикс. In-app тост виден только при открытом приложении, а это поздно для
того, у кого сборка сломана настолько, что он перестал её открывать.

Сам воркер тоже живёт в общем throttled-бюджете фона, поэтому дважды в сутки, а не чаще:
приоритет у прогноза.

## Известные ограничения

- **Huawei без Google Play Services** — FCM не работает. Решение: RuStore Push (VK SDK),
  закладывать после дедлайна конкурса.
- Пользователь может сделать Force Stop — тогда не доходит ничего, включая пуш, пока
  приложение не откроют снова. Это поведение Android, обойти нельзя.
