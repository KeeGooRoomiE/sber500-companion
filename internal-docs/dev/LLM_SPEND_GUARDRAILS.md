# LLM-траты: агентный жор, гардрейлы, аудит

Документ про риск неконтролируемых LLM-трат от **агентных/внешних инструментов**, подключённых к общему ключу акселератора. Повод — инцидент 2026-10-14.

---

## Инцидент 2026-10-14: ~19.5k за сломанную интеграцию

**Что было.** Ключ акселератора (`LLM_API_KEY`, прокси `shared1.multitool.works`) подключили к **Axenta AI Apps** для сборки дашборда со своей OpenAI-совместимой моделью. Интеграция не заработала — приложение не смогло подтянуть список машин клиента через сервисный API. Агент **зацикливался на ретраях**, пересылая весь растущий контекст в самую дорогую модель.

**Цифры (из прокси `/key/info` + `/spend/logs`, сверено до копейки):**

| модель | вызовов | спенд ₽ | prompt-токенов | окно MSK |
|---|---|---|---|---|
| **claude-opus-4.6** | 296 | **19 521** | **19.57 млн** | 11:53–14:34 |
| gigachat-3-pro (наше приложение) | 2480 | 120 | 5.96 млн | за всё время |
| gpt-4.1-mini + мелочь | ~40 | ~45 | ~0.55 млн | — |
| **ИТОГО по ключу** | — | **19 686** / 75 000 бюджета | 26.35 млн | |

**Почему так дорого (главный урок).** Дело **не в числе вызовов** (296 — немного), а в том, что:
1. агентный тул **пересылает весь контекст на каждом шаге** → ~66k промпт-токенов на вызов (19.57М / 296);
2. это шло в **Opus** — самую дорогую модель;
3. **сломанная интеграция усилила жор** — агент ретраил на ошибке, каждый раз заново отправляя накопленный контекст.

То есть «проба, которая даже не заработала» стоила 19.5k именно потому, что не заработала: рабочая интеграция уложилась бы в десяток вызовов.

**Реакция.** Траты замечены → интеграция сразу отключена и удалена. Блэк-рэдиус ограничен: израсходовано 26% бюджета (75k), осталось ~55k. Продакшн-приложение не задето (gigachat — 120₽ за всё время).

## Гардрейлы на будущее

1. **Отдельный ключ под эксперименты.** Никогда не подключать продакшн-ключ приложения к внешним агентным тулам (vibecode, AI App builders, автономные агенты). Если акселератор даёт пер-проектные ключи — эксперименты только на отдельном.
2. **Агентным тулам — только дешёвая модель.** gpt-4.1-mini / gigachat / deepseek, **никогда Opus/топ-модель для автозадач.** На 66k-промптах Opus это ~×100 к косту.
3. **Лимиты на ключе.** У ключа `accelerator` все предохранители `null` (нет rpm_limit, нет дневного budget_duration) → рунэвэй-тул может спалить весь остаток за часы. Если есть доступ к настройкам ключа — поставить rpm/дневной cap.
4. **Следить за размером контекста.** Главный множитель стоимости — токены на вызов × цена модели × число ретраев, а не число вызовов. Сломанный агентный цикл на дорогой модели — худший сценарий.

## Как аудитить траты (воспроизводимо)

Прокси — LiteLLM-совместимый. Авторизация — `Authorization: Bearer $LLM_API_KEY` (ключ из `backend/.env`, в вывод не печатать).

- **Итого по ключу:** `GET {BASE}/key/info` → `spend`, `max_budget`. Это **наш** ключ, авторитетный итог.
- **Пореквестно по нашему ключу:** `GET {BASE}/spend/logs?api_key=<sha256(ключ)>` → список вызовов с `spend`, `prompt_tokens`, `completion_tokens`, `startTime`, `model_group`. Хэш ключа = `sha256(key).hexdigest()`.
- **Важно:** `/spend/logs` без фильтра **глобальный** (прокси общий, 57+ ключей) и обрезан на 10 000 последних записей — фильтровать по хэшу своего ключа обязательно.
- Токены/кост нашего приложения (gigachat) отдельно лежат в БД: `morning_messages`, `reviews`, `explore_answers` (`prompt_tokens`, `completion_tokens`), стоимость считается в `backend/internal/api/metrics.go` (`LLMCostRubTotal`).

`BASE` = `LLM_BASE_URL` без хвоста `/v1`. Персональные данные (имена/контакты/содержимое) в аудите не используются.
