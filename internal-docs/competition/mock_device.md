# mock_device — демо на эмуляторе: онбординг + готовая история

Как записать непрерывный walkthrough (онбординг → Home с богатыми данными) на эмуляторе, не
имея реальных сенсоров. Онбординг показываем как есть, историю подкладываем инъекцией токена
мок-персоны. Для Формы 3 (демо MVP) — форма прямо разрешает «подготовить аккаунт и данные».

**Статус:** обкатано 2026-10-15 (весь прогон прошёл, панели наполнены). Запись — 2026-10-16.

> ⚠️ **Seed привязан к дате: весь сетап прогоняется ЗАНОВО в день записи.** Seed кладёт данные
> так, что последний день = «вчера» относительно дня запуска. Сетап от 15.10 на 16.10 протухает
> («вчера» уедет на пустой день, тяжёлый день окажется позавчера, прогрет кэш не за тот день).
> Поэтому утром 16.10: `purge` → `seed` → токен → инъекция → прогрев → бэкфилл прошлых прогнозов.

---

## 1. Почему это работает (онбординг и история развязаны)

- **Онбординг не создаёт аккаунт.** `NavHost.setOnboarded()` флипает локальный флаг и всё;
  регистрация (`DeviceCredentials.register`) происходит отдельно и **лениво** — только при первом
  авторизованном запросе, если токена ещё нет.
- **Личность = токен в SharedPreferences `device_auth`** (`user_id` + `token`). Авторизация:
  `Authorization: Bearer <token>` → `sha256_hex(token)` → `SELECT id FROM users WHERE token_hash=…`
  (`middleware.go` + `repo/user.go:ByToken`).
- **Флаг `isOnboarded`** лежит в другом хранилище (DataStore `companion_prefs`, ключ `onboarded`)
  и на свежей установке отсутствует → онбординг показывается.

Значит: свежая установка (онбординг виден) **+** подложенный токен мок-персоны (история есть) =
и то, и другое одновременно, одним дублем.

**Токен-модель (точно):** `HashToken = hex(sha256(token))` — строчный hex, совпадает с
`shasum -a 256`. Мок-персоны сеются только в `daily_data` + `checkins` (см. `mock.Seed`), строки
в `users` у них нет — поэтому «выпустить токен» = вставить `users`-строку с `id='mock_remote'` и
`token_hash` нашего токена.

## 2. Персона: `mock_remote` (основная)

«Удалёнщик: Telegram рабочий, вчера чаты весь день и до ночи.» Выбрана потому, что **вчера =
тяжёлый день**, значит и утренний прогноз, и вечерний разбор бьют в одну драматичную точку, и
это ровно ICP-триггер «залипает в телефоне и не понимает почему». Полные данные сна всю неделю.

| День | Сон | Экран | Разблок. | Шаги | Чек-ин |
|---|---|---|---|---|---|
| d1 | 7ч18 | 211м | 58 | 3273 | ok |
| d2 | 7ч12 | 244м | 65 | 4498 | ok |
| d3 | 7ч03 | 214м | 61 | 3523 | ok |
| d4 | 7ч21 | 218м | 57 | 3695 | meh |
| d5 | 7ч20 | 231м | 64 | 3350 | ok |
| d6 | 7ч05 | 242м | 55 | 4240 | meh |
| **d7 (вчера)** | **6ч15** | **320м** | **104** | **2100** | **hard** |

Вчера: экран подскочил до 5ч20м (норма ~3ч45м), разблокировки удвоились до 104 (норма ~60),
сон просел. Прогноз: «после такого дня утро обычно медленнее»; разбор: «вчера тяжело — чаты весь
день, 104 разблокировки, сон короче».

**Альтернативы:**
- `mock_week` — вчерашний день «meh», но внутри недели яркий провал в среду (сон 4ч58, экран
  341м, 91 разблок., шаги 1820) + восстановление. Лучшая **недельная сводка** (домино+отскок);
  если герой демо — «Итоги недели», бери её, а разбор тяжёлого дня открывай через историю.
- `mock_calls` — вчера «hard», история «утро звонков + Slack», тоже полный сон.

## 3. Пошаговый прогон (в день записи)

Предусловия: `ANDROID_HOME` c эмулятором и adb; SSH-алиас `companion`; **debug-APK**
приложения (нужен для `run-as`, см. гейт ниже); пакет `ru.keegoo.companion`.

### 3.1 Поднять эмулятор (с рамкой устройства)
```bash
"$ANDROID_HOME/emulator/emulator" -avd Pixel_9 &
# AVD Pixel_9 уже со skin pixel_9 — окно с безелем, Android Studio не нужна
```

### 3.2 Засеять персон (даты заканчиваются вчера — сеять в день записи)
```bash
bash deploy/prompt.sh companion seed
# фоллбэк, если нет сабкоманды: ssh companion 'curl -s -X POST -H "Authorization: Bearer $ADMIN_TOKEN" http://127.0.0.1:9090/admin/mock/seed'
```

### 3.3 Выпустить токен для mock_remote (прод-write, делаем сейчас, отзываем после)
```bash
TOKEN=$(openssl rand -hex 16)
HASH=$(printf %s "$TOKEN" | shasum -a 256 | cut -d' ' -f1)
ssh companion "set -a; . /opt/companion/.env; set +a; psql \"\$DATABASE_URL\" -c \
  \"INSERT INTO users (id, token_hash, is_dev) VALUES ('mock_remote','$HASH',true) \
    ON CONFLICT (id) DO UPDATE SET token_hash=EXCLUDED.token_hash;\""
echo "TOKEN=$TOKEN"   # понадобится в 3.4 и 3.5
```
`is_dev=true` — на всякий случай; `mock_remote` и так исключён из метрик по маске `mock\_%`.
Если `id` не PK/unique (ON CONFLICT упадёт) — заменить на `DELETE FROM users WHERE id='mock_remote';`
перед `INSERT`.

### 3.4 Подложить токен в приложение (ДО первого запуска!)
Иначе первый авторизованный запрос зарегистрирует новый пустой аккаунт.

**Проверено на Pixel_9 (PlayStore-образ, SELinux Enforcing, user-build):** `run-as` читает и
**пишет** в `shared_prefs/`. Домашняя папка — `/data/user/0/ru.keegoo.companion`.

Если приложение уже установлено/онбордено с прошлой сессии (флаг `onboarded=true` → онбординг
не покажется) — сбросить данные, чтобы онбординг вернулся:
```bash
adb install -r app-debug.apk               # debug-сборка
adb shell pm clear ru.keegoo.companion     # сброс: onboarded=false, старый токен стёрт
```

Надёжный способ (проверено): писать **внутри `run-as` через base64**. Прямой `cat >`/stdin и
`cp` с `/sdcard` не работают — у app-uid нет прав читать запушенный на sdcard файл, а stdin в
`adb shell run-as` рвётся. base64 обходит и права, и кавычки.
```bash
PKG=ru.keegoo.companion; H=/data/user/0/$PKG
TOKEN=ВСТАВИТЬ_TOKEN_ИЗ_3.3
XML="<?xml version='1.0' encoding='utf-8' standalone='yes' ?>
<map>
    <string name=\"user_id\">mock_remote</string>
    <string name=\"token\">$TOKEN</string>
    <boolean name=\"had_token\" value=\"true\" />
    <boolean name=\"restore_pending\" value=\"false\" />
</map>"
B64=$(printf '%s' "$XML" | base64 | tr -d '\n')
adb shell "run-as $PKG mkdir $H/shared_prefs" 2>/dev/null   # после pm clear папки может не быть
adb shell "run-as $PKG sh -c 'echo $B64 | base64 -d > $H/shared_prefs/device_auth.xml'"
adb shell "run-as $PKG cat $H/shared_prefs/device_auth.xml"  # проверить
```
Приложение до инъекции **не открывать**.

### 3.5 Прогреть LLM-кэш (чтобы в неразмонтированном дубле всё рисовалось мгновенно)
У прокси ~33% ошибок и задержка 2–17с — живьём рисковать нельзя. Кэш — по (user, kind, день).
```bash
BASE=https://api.94-183-236-169.sslip.io
curl -s -H "Authorization: Bearer $TOKEN" "$BASE/api/v1/morning" >/dev/null
curl -s -H "Authorization: Bearer $TOKEN" -X POST "$BASE/api/v1/review/day"  >/dev/null  # вчера = тяжёлый день
curl -s -H "Authorization: Bearer $TOKEN" -X POST "$BASE/api/v1/review/week" >/dev/null
```

### 3.5a Прошлые прогнозы (панель «Прошлые прогнозы»)
Seed не создаёт `morning_messages`, а штатного эндпоинта «сгенерить прогноз за прошлую дату» нет
(`Ensure(date)` вызывается только для «сегодня»). Поэтому прошлые прогнозы бэкфиллим вручную:
1. Сгенерировать 2-фразовые прогнозы за прошлые дни **через LLM-прокси напрямую** (как тест-скрипты:
   `morning_system.md` + контекст дня из канонических чисел персоны). Мимо бэкенда → без бюджета
   и `call_log`. Прокси нестабилен → ретраи.
2. `INSERT INTO morning_messages (user_id,date,message,sent_at)` за каждый прошлый день (минимум
   этих колонок, остальные NOT NULL — по дефолтам).
3. Для отметок «Совпало/Не совсем» — `INSERT INTO feedback (user_id,'morning',date,verdict)`,
   `verdict ∈ hit|miss`. ~80% hit = реалистично (реальные ~79%).
4. Проверка — `GET /api/v1/history` с токеном: вернёт заполненную панель (дата, текст, verdict).

Готовый скрипт/SQL последнего прогона — в scratchpad сессии (`past_forecasts.json`, `past.sql`).

### 3.6 Запуск и запись
```bash
adb shell monkey -p ru.keegoo.companion -c android.intent.category.LAUNCHER 1
# запись контента (без безеля): adb exec-out screenrecord --time-limit 180 /sdcard/demo.mp4 ; adb pull /sdcard/demo.mp4
# запись С рамкой: захват окна эмулятора средствами macOS (QuickTime)
```
Проходишь онбординг → Home авторизован как mock_remote → прогноз/разбор/неделя наполнены.

### 3.7 Teardown (после записи)
```bash
bash deploy/prompt.sh companion purge
```
`purge` чистит по маске `mock\_%` все дочерние таблицы (`feedback`, `morning_messages`,
`reviews`, `checkins`, `daily_data`, `user_activity`, `explore_answers`, `weekly_feedback`) **и**
строку `users` mock_remote — в правильном FK-порядке. Это и есть отзыв токена.

⚠️ Простой `DELETE FROM users WHERE id='mock_remote'` теперь **упадёт** по FK: на него ссылаются
`morning_messages`/`feedback` (прошлые прогнозы). Поэтому только `purge` (или удалять детей раньше
родителя).

## 4. Гейты и ограничения

- **Нужна debug-сборка** — `run-as` работает только на debuggable-приложении. AVD `Pixel_9` на
  **PlayStore-образе**, где `adb root`/`run-as` на релизе заблокированы. Это единственный шаг
  «сборки»; одноразовый инструмент под запись, не релиз/версия/тег. Альтернатива — новый AVD на
  **google_apis** (не-PlayStore) образе, где `adb root` работает на релизе (но образ докачивать).
- **Плитки «сегодня» (экран/сон/шаги) останутся пустыми** — они читаются из локальных сенсоров
  эмулятора, не с сервера. Богатые — карточки прогноза/разбора/недели. Вести рассказ по ним; если
  пустая плитка в кадре — «на эмуляторе сенсоров нет, на реальном телефоне тут живые цифры».
- **Пустой бэкфилл безопасен.** После онбординга `DailyCollectWorker` шлёт только дни с данными;
  на пустом эмуляторе и вчера, и сегодня пустые → не отправляются → серверная история mock_remote
  не затирается.
- **Порядок критичен:** токен подложить ДО первого запуска; сеять в день записи (даты → вчера).
- **Метрики не загрязняются:** mock_remote под маской `mock\_%` + `is_dev=true` исключён из 50
  реальных пользователей (их показываем отдельно со страницы метрик).

## Фактический прогон — демо Форма 3 (2026-10-15 … 16)

Запись сдана 16.10. Ниже — как всё реально проходило, какие данные и как использовались,
как писались и как чистились мок-данные. Teardown выполнен, прод чист.

### Что использовали
- **Персона `mock_remote`** («удалёнщик: рабочие чаты до ночи»), неделя заканчивается «вчера».
  Выбрана за то, что вчера = тяжёлый день → и утренний прогноз, и разбор вчера бьют в одну точку.
  Канонические числа дней — из `personas.json`.
- Эмулятор **Pixel_9** (`-gpu host`, Metal — плавно; в Android Studio было ~15 fps из-за софт-рендера).
- **debug-APK** (`assembleDebug`) — единственная «сборка», нужна для `run-as` (образ PlayStore,
  `adb root`/`run-as` на релизе закрыты).

### Как писали мок-данные (всё под `mock_remote`, из метрик исключён)
1. **Онбординг вернули** локально: `adb shell pm clear ru.keegoo.companion` (флаг `onboarded`
   лежит в DataStore, сбрасывается вместе с данными; `device_auth` тоже стирается).
2. **Сид** персон: `prompt.sh companion seed` (POST `/admin/mock/seed`) → `daily_data` + `checkins`,
   даты заканчиваются вчера.
3. **Токен** для mock_remote: сгенерили случайный, `token_hash = hex(sha256(token))`, и
   `INSERT INTO users (id,token_hash,is_dev) VALUES ('mock_remote', <hash>, true) ON CONFLICT (id)
   DO UPDATE …` через `psql` по ssh. Живой токен держали только в scratchpad сессии, в репо не клали.
4. **Инъекция** `device_auth.xml` (user_id=mock_remote + token) в `shared_prefs` через
   `run-as` + **base64** (прямой `cat >`/`cp` с /sdcard не работает по правам/кавычкам). До первого
   запуска — иначе приложение зарегистрировало бы новый пустой аккаунт.
5. **Прогрев кэша** (чтобы в неразмонтированном дубле всё рисовалось мгновенно, прокси ~33% ошибок):
   `GET /morning`, `POST /review/day`, `POST /review/week` с токеном, с ретраями.
6. **Прошлые прогнозы** (панель «Прошлые прогнозы»): штатного бэкфилла нет (`Ensure(date)` только
   для «сегодня»), поэтому 6 прогнозов за прошлые дни сгенерили **через LLM-прокси напрямую** (мимо
   бэкенда → без бюджета и `call_log`), `INSERT` в `morning_messages` + несколько строк в `feedback`
   (hit/miss, ~80% — как реальные ~79%). Проверка — `GET /history`.
7. **Между дублями** (пользователь проходил онбординг на тесте и запарывал дубли): `pm clear` +
   повторная инъекция токена — «чистый вход» за секунды. Серверные данные при этом не трогали.

### Date-relativity (важный урок)
Сид привязан к дате (последний день = «вчера»). Сетап от 15.10 на 16.10 протух → утром 16.10
**весь прогон повторили заново** (purge → seed → токен → инъекция → прогрев → бэкфилл), чтобы
тяжёлый день встал на 15.10 = «вчера».

### Как чистили (teardown, 16.10 после записи)
- `bash deploy/prompt.sh companion purge` (POST `/admin/mock/purge` → `mock.Purge`): удаляет по
  маске `mock\_%` все дочерние таблицы (`explore_answers, feedback, reviews, morning_messages,
  checkins, daily_data, user_activity, weekly_feedback`) **и** строку `users` mock_remote — в
  правильном FK-порядке. Это и есть отзыв токена.
- Проверка: `GET /morning` со старым токеном → **HTTP 401**; `SELECT count` по `mock\_%` в
  users/morning_messages/daily_data/feedback → **0/0/0/0**.
- Локальные токен/SQL из scratchpad удалены.
- Эмулятор оставлен запущенным (данные приложения не трогали — там инъекция на уже мёртвый токен;
  при желании `adb shell pm clear` или закрыть окно).

### Метрики не пострадали
Фильтр метрик строится как `id LIKE 'mock_%' OR is_dev` и уходит во все запросы
(`NOT (user_id = ANY(...))`). mock_remote исключён двойне (префикс + is_dev); генерацию прошлых
прогнозов делали мимо бэкенда, так что и в `call_log`/бюджет ничего не попало.

### Результат
Видео `Companion_video.mp4`: 5:30, H.264 1724×1080@60, AAC-звук (голос), ~63 МБ, один дубль без
склеек. В кадре: вход → онбординг → Home (прогноз + «Прошлые прогнозы» с отметками) → пуш «Разбор
дня» → профиль/вопросы → страница метрик (когорты, группа 50, вызовы по механикам, бюджет).
