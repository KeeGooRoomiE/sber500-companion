# План по дизайну

Что делаем с иконкой, экранами и орбом, что передаём дизайнеру ИТМО. Задачи: DS-01..DS-07, AND-02, AND-03, AND-08, AND-11..AND-14 в [TASKS.md](TASKS.md).

## Принципы (сходятся во всех исследованиях)

- Наблюдатель, не коуч: без стриков, очков, «долга» за пропуск, повелительного наклонения.
- Объяснять, а не оценивать: карточка с причинами вместо одного балла.
- Орб это лицо продукта: он должен отражать прогноз (а не быть фоном).
- Честные пустые состояния: если нет данных, сказать почему и когда появятся.
- Приватность на виду: где считаются данные, что уходит в облако.
- Доступность: режим «убрать анимацию».

## 1. Иконка (DS-01)

Источник: [ICON_DESIGN_RESEARCH](../research/design/ICON_DESIGN_RESEARCH.md), картинки в `internal-docs/research/icon/`.

1. Три финалиста: **чёткая жемчужина**, **орб со свечением**, **контрольный вариант** (текущая).
2. Риск: пара «тёмный фиолетовый + розовый шар» занята приложением Mind Tracker. Развести цветом или формой.
3. Тест: 48 px на домашнем экране и размер листинга RuStore, на оставшихся интервью (3–5 человек, вопросы: «что это за приложение», «что откроете первым»).
4. Ассеты после выбора: PNG 512 для RuStore, адаптивная иконка Android (передний и задний слой, монохромный слой для тематических иконок), обновить `web/`.

## 2. Брейншторм экранов с дизайнером (DS-02)

Форма ИТМО до 01.11 15:00, воркшоп 03.11.

**Что передать:**
- Краткое описание продукта: Android-компаньон на пассивных данных телефона (экран, шаги, сон), утренний прогноз, вечерняя отметка, разбор дня, недельный итог.
- Варианты главного экрана: `internal-docs/research/home/` (панель сравнила варианты; все лучше текущего: 8.2 против 5.2), текущие экраны `web/screens/`.
- Лучший вариант: **гибрид «утро/день»**, он же направление для брейншторма.
- Исправления, которые нужно сохранить: орб связан с прогнозом; днём «Как идёт день?»; нейтральные цвета метрик (без «красно-зелёного»); вечером чек-ин поднят; «Совпало?» уходит в историю.

**Вопросы дизайнеру:**
1. Как показать три состояния орба (спокойный, напряжённый, пустой) без шкалы «хорошо/плохо»?
2. Как оформить чек-ин (три состояния, необязательные теги, ответ в одно касание) и награду после него?
3. Первое утро без данных: что показать вместо прогноза?
4. Как показать «где считаются данные» без юридического тона?
5. Как провести онбординг так, чтобы ценность появилась до запроса разрешений (pre-permission экран с мок-пушем)?

**Ограничения:** Jetpack Compose, Material 3, тёмная и светлая темы, 360 dp и выше, анимации не тяжелее процедурного орба на среднем устройстве, русский язык, тон из [UX_DESIGN_RESEARCH](../UX_DESIGN_RESEARCH.md).

## 3. Орб (DS-04)

| Вариант | За | Против |
|---|---|---|
| Rive | state machine, data binding: орб реагирует на данные | новая зависимость, нужен дизайнер Rive |
| Lottie | знакомый инструмент | нет state machine |
| Процедурный Compose Canvas (сейчас) | уже работает, ноль зависимостей | сложнее выразить новые состояния |

Предложение: оставить процедурный орб, провести эксперимент Rive на одном состоянии, если дизайнер из ИТМО владеет Rive.

Тест пяти секунд: текущий главный, «Гибрид: утро», «Герой-орб»; вечер отдельным вариантом. Модельная панель больше информации не даст.

## 6. Что не делаем

Стрики, очки, значки, красно-зелёная шкала качества, романтический тон, сравнение с другими людьми, уведомления с чувством вины.
