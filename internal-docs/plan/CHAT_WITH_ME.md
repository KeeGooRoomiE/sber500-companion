# «Обсудим?» — тестовая версия чата Companion

Ветка `chat-with-me`, база `e698415`. Этот документ описывает реализацию и приёмку APK на устройстве Александра.

## Сценарий

1. На месте «Узнать больше» появляется **«Обсудим?»**. Тап сразу открывает третий полноценный экран. В ленте от имени пользователя появляется **«Расскажи подробнее про сегодняшний день»**. Companion отвечает по имеющимся данным и явно обозначает, за какую часть дня они собраны.
2. Внизу закреплено растущее многострочное поле ввода. Над ним в один горизонтальный ряд помещены 2–3 короткие пилюли по текущей теме и доступным данным. Тап отправляет выбранный текст. Оба способа ввода работают в одной ленте. Клавиатура оставляет видимыми поле и кнопку отправки.
3. Пользователь может продолжать беседу без дневного лимита сообщений. Один ответ Companion — максимум **1 000 отображаемых символов**. Ограничение проверяется и сервером. Для списка памяти длиннее одного ответа предусмотрено продолжение «Показать ещё».
4. «Доступен новый вопрос» ведёт в этот же чат к сообщению **от Companion**. Пользователь отвечает пилюлей или своим текстом. Ответ попадает в существующий механизм ежедневных вопросов. Один вопрос имеет стабильный ID: повторная доставка или открытие баннера возвращает к уже добавленному сообщению.
5. Предложенная семантика входа: первое нажатие «Обсудим?» за локальный день отправляет стартовую реплику один раз. Следующее открывает текущую переписку. Переход по ежедневному вопросу показывает сам вопрос. Возврат из фона, поворот и восстановление процесса сохраняют состояние без повторной отправки.

## Экран и длинная история

* Верх экрана использует тот же анимированный `CompanionOrb`, что и экран вопросов. Сообщения уходят под верхнюю градиентную маску. Движение учитывает фактические экранные границы ответа и области персонажа. Пока видимые строки ответа пересекают траекторию, персонаж остаётся в верхней панели.
* Сразу после отправки в точке будущего ответа появляется анимация ожидания. При готовности её заменяет текст на том же месте. При ошибке там появляется действие «Повторить». Во время чтения старой части переписки новый ответ не отбирает позицию прокрутки.
* История хранится на устройстве с привязкой к пользователю. При входе загружается последняя страница. Более ранние сообщения подгружаются при прокрутке по стабильному курсору. Стабильные ID и якорь прокрутки сохраняют место при вставке страницы. Тестовый объём — 1 000+ сообщений, включая длинные ответы, emoji, незавершённую отправку и перезапуск приложения.

## Ответы, контекст и серверная память

* Используем ту же настроенную модель, что и основной Companion. Разрешённый контекст охватывает накопленные данные пользователя на устройстве и в базе, его профиль, сохранённую память и историю разговора. Для конкретного ответа выбираются релевантные показатели, даты и реплики. Полная локальная история доступна для поиска по мере необходимости. Размер входа к модели ограничен независимо от длины ленты.
* Тематика — личные данные, сравнения, режим, оценки, ежедневные вопросы и память. Другие темы возвращают короткую реплику вроде «Давай поговорим о тебе. Что хочешь узнать про свой день?» и релевантные пилюли. Личные интерпретации опираются на доступные наблюдения. Неизвестные факты обозначаются явно.
* Команда **«Хочу, чтобы ты запомнил обо мне…»** создаёт или уточняет серверный факт в памяти текущего авторизованного пользователя. Пример: «Работаю по ночам». После успешной записи чат сообщает, что сохранено. Новый факт учитывается в чате и последующих разборах: ночной график меняет интерпретацию экрана в 02:00, при этом измеренное время остаётся исходным. При противоречии новая явная поправка заменяет устаревший факт, неоднозначную поправку Companion уточняет.
* На «Что ты обо мне помнишь / знаешь / что я просил запомнить?» сервер читает блок памяти этого пользователя. Модель формулирует список только по сохранённым записям. Пустая память, исправление записи и повторная доставка той же команды имеют определённый результат. Текст факта используется как пользовательские данные и не меняет правила ответа, границы доступа или вызова операций. Желательное дополнение для первой версии — «забудь этот факт».
* Сервер устанавливает владельца запроса по существующей авторизации. Один пользовательский запрос имеет стабильный ID. Повтор после сетевого сбоя не дублирует ответ, запись памяти или ежедневный вопрос. Ограничения на параллельность, время ответа и размер контекста совместимы с неограниченным числом последовательных сообщений. Стоимость проверяется по фактическому использованию модели на длинной истории.

## Аналитика

| Что измерить | Как интерпретировать |
|---|---|
| Количество запрошенных сообщений | Событие отправки с ID запроса, источником `starter / pill / typed` и числом уже сохранённых сообщений **до вставки** новой реплики. При повторе сохраняется ID. |
| Ежедневные вопросы | Отдельный признак сценария `daily_question` и ID вопроса. Сообщение от Companion и ответ человека учитываются раздельно. Для ответа сохраняется реальный способ ввода. |
| Исход отправки | Успешный ответ, возврат к теме, ошибка или отмена, задержка и число обращений к модели. Для вопроса о памяти и её изменения сохраняется тип операции. Текст бесед и содержимое памяти в продуктовые события не отправляются. |
| Вклад в Calls/DAU | Реальные обращения к LLM и инструментам проходят через существующий `call_log` с пользователем, временем, сессией, компонентом, триггером, видимостью, результатом и задержкой. Отдельно считать стартовые и добровольные последующие реплики, долю участников, вернувшихся в другой день, и концентрацию вызовов. Тестовое устройство исключается из конкурсных показателей. |

## Порядок реализации и проверка

1. **Сервер.** Контракт сообщения с ID, контекст, выбор темы, ответ до 1 000 символов, память пользователя, журнал и повтор запроса. Проверки на двух тестовых пользователях, при пустой истории, отсутствии данных, посторонней теме, длинном ответе и сбоях.
2. **Android.** Локальная таблица сообщений и пагинация, новый экран, навигация с «Обсудим?», Lottie, градиент, поле ввода и пилюли. Проверка длинного ответа при обеих направлениях прокрутки, с открытой клавиатурой и при возвращении из фона.
3. **Ежедневные вопросы и измерение.** Перенести вход и ответы, проверить сохранение существующего статуса вопроса. Сверить источники сообщений, глубину ленты и фактические вызовы модели по одной тестовой беседе.
4. **Тестовый APK.** Вариант `chatTest` ставится рядом с Companion как `ru.keegoo.companion.chat`. GitHub Actions сохраняет APK как артефакт ветки. По умолчанию приложение обращается к `http://127.0.0.1:18080/`. На компьютере должен работать сервер ветки на этом порту с миграциями до 019. После подключения телефона с USB-отладкой запустить `adb reverse tcp:18080 tcp:18080`. Для отдельного HTTPS-стенда передать `-PchatTestApiUrl=https://адрес/` при сборке или задать `CHAT_TEST_API_URL` в переменных GitHub Actions.
5. **Приёмка владельцем.** Проверить на устройстве личный вопрос, постороннюю тему, устойчивость тематических границ, запоминание и чтение после перезапуска, ответ на ежедневный вопрос и длинную историю. Публикация релиза и выкатка в production — отдельное решение после этой проверки.
