Category Deep-Dives

Oura — Design Case Study

Design agency: Instrument. Redesigned 2024–2025 to connect daily tracking to long-term health narrative.
  • Progressive disclosure5 tabs condensed to 3 (Today, Vitals, My Health). Users see what they need at their level.
  • 3-level visualization depthAbstract at-a-glance rings → mid-level metric cards → exploratory long-term charts. Same data, 3 depths.
  • Semantic color = dataApp zones change color based on biometrics. Green readiness, amber moderate, red recovery. Color communicates state instantly without reading.
  • Short-term to long-term narrativeCore insight: connect today's sleep score to 90-day trend. Not just "how did you sleep" but "here's what's changing."

AI Companion Design Lessons

  • Replika lessonEmotional design drives retention more than features. People return to apps that understand, adapt, feel alive. But avatar realism risks uncanny valley.
  • Wysa lessonNon-human mascot (penguin) reduces stigma around health. Mascot creates emotional safety + distance simultaneously.
  • Woebot lessonClinical efficacy ≠ retention. Woebot had Stanford RCT data but shut down 2026 — overly clinical feel without emotional warmth.
  • Focus Friend lessonWon 2025 Play Award. Single animated character reacting to user behavior = more engagement than feature lists.

Material Design 3 (Material You)

Dynamic Color System

  • HCT color spaceHue–Chroma–Tone. Perceptually uniform, better than HSL. Algorithm extracts palette from wallpaper and generates accessible scheme.
  • Color rolesPrimary, Secondary, Tertiary, Error — each with Container + On-Container pairs. 12 surface tones total. Dark theme uses tonal elevation, not shadow.
  • Tonal elevation in dark themeSurface, Surface+1...+5 — each level adds tonal color overlay. Replaces invisible dark-on-dark shadows. Critical for premium dark feel.
  • Auto light/dark generationBrand seed color generates both light + dark themes automatically. Accessible contrast ratios built in.

Typography Scale

2025 trend: Large display type as a design element, not just information. "Big, expressive text with large headlines" — morning greeting in Display Large is a moment, not a label.

Motion System — Spring Physics

  • Spring attributesstiffness (how fast), damping (how much bounce fades), initial velocity. Three speed tokens: default / fast (small elements) / slow (large elements).
  • 21 components use spring by defaultIn Jetpack Compose, M3 components already use spring physics. You get physics for free with material components.
  • Container TransformShared element: element grows from its source position into a new screen. Best pattern for card → detail transitions.
  • Timing targets300ms: content changes. 150ms: micro-interactions (tap, toggle). 500ms+: page transitions. Don't make users wait for UI.

Material 3 Expressive (May 2025)

Not "Material 4" — extension of Material You, released alongside Android 16. Research base: 46 studies, 18,000+ participants across the globe.

What Changed

ChangeDetails
15 new/refreshed components Button groups, split buttons, toolbars, loading indicators, FAB variants. More shape/color configuration per component.
Spring physics everywhere Motion now mimics spring physics throughout — elastic in/out rather than cubic bezier. Feels alive, not mechanical.
Containment patterns Contrasted shades within rounded containers signal "this group belongs together." Visual hierarchy through containment, not just size.
Adaptive components Components reflow for phone/tablet/foldable/watch automatically. One component definition, many form factors.
Expressive typography More weight/width variation within a single typeface. Bold display moments now explicit in guidelines.

Apps need to be accessible to as wide a range of users as possible. Content descriptions, touch targets ≥48dp, support for system font scaling.

Based on design quality, functionality, overall UX, and appeal. User ratings inform but editors override for quality.

Design Patterns That Make Apps Feel Premium

Core insight: "Premium is almost never a redesign — it's a thin layer of polish sitting on top of an ordinary layout."

Loading States

  • Skeleton screens over spinnersShow layout shape while loading. Facebook pioneered this; now table stakes for premium. Shimmer animation across whole screen (synchronized, not per-card).
  • Tasks >10s: percent progressNever leave user without feedback on long operations. Show real progress bar with % or step count.
  • Lottie for branded loadingVector animations, tiny files, crisp at every density. Far better than GIFs or static illustrations. Use for brand moments in onboarding and empty states.
Compose shimmer — JetBrains Mono for code
// Shimmer effect on any composable Modifier.shimmerEffect() // from compose-shimmer-skeleton lib // Auto-synchronized across screen, customizable color/speed // Lottie in Compose val composition by rememberLottieComposition( LottieCompositionSpec.RawRes(R.raw.morning_loading) ) LottieAnimation( composition = composition, iterations = LottieConstants.IterateForever )

Onboarding

  • Value prop before permission dialogExplain WHY you need location/notifications with a custom screen BEFORE the system dialog. Acceptance rate 2–3× higher.
  • Progressive revelationDon't show all features at once. Unlock features as user completes steps. Reduces overwhelm, increases activation.
  • First session = one satisfying momentDeliver ONE thing that makes the user say "oh, this is useful" before asking for anything. Design for the first-session aha.

Empty States

  • Never just a message"Apps that show clear paths in empty states see feature adoption jump by 80%." Always provide a next action.
  • Lottie animation + clear actionSmall branded animation + 1 button. Turns a dead end into a guided moment.
  • Example: sber500-companion first run"Данных пока нет. Носи телефон с собой сегодня, и завтра утром появится первый прогноз." + animated icon of sleeping phone.

Micro-Interactions

  • Button pressScale 0.95x + color shift, 150ms spring. Makes every tap feel physical and responsive.
  • Checkmark / completionAnimated draw-on (not instant appear). Satisfying mechanical feel. Daylio and Loop do this perfectly.
  • Metric counter animationScore/number updates with animated counter (countup animation), not instant swap. "87" counting up from previous value feels earned.
  • Haptic feedbackOn meaningful actions (check-in completed, goal reached) — not every tap. Medium impact on completion, light on selection.
  • Card swipe / physics dragFollow finger with spring return. Makes UI feel like physical objects.

Jetpack Compose Animation Patterns

Navigation & Information Architecture

  • 3 taps maximumAny critical function reachable in ≤3 taps. For a companion app: 1 tap to see forecast, 2 to see history, 3 to change settings.
  • Bottom nav: 3 destinationsToday / History / Settings. No more than 3 for a focused companion app. More tabs = feature bloat signal to judges.
  • Contextual FABFAB changes per screen — Today: "Log mood", History: "Export", Settings: hidden. Signals thoughtful UX.

Personalization Signals

  • Name in key moments"Доброе утро, Александр" in Display Large. This is a moment, not a label. Users notice and remember this.
  • Personal averages, not population norms"Your usual step count" vs "10,000 steps recommended." Personal baseline makes insight feel earned.
  • Contextual remindersTriggered by behavior deviation (fell below own goal), not fixed schedule. "Strongest engagement pattern" per 2025 health app research.

Recommendations for sber500-companion

Specific to: Kotlin/Compose, morning forecast + evening check-in, passive health/usage data, UX nomination.

Must-Have for UX Nomination

1
Spring physics on all interactive transitions

Not tween/linear. spring(dampingRatio = 0.7f, stiffness = 200f) everywhere interactive. 21 M3 components do this for free.

2
Semantic color system for health state

Like Oura: green = great day ahead, amber = moderate, red = rest day. Color communicates readiness without reading. Instant comprehension.

3
Progressive disclosure on morning card

1 insight visible → tap to expand → tap again for full data. Like Oura's 3-level visualization. Don't dump all data on screen.

4
Named greeting in Display Large

"Доброе утро, Александр" — 57sp, font-weight 300. This is a moment, not a label. Users remember this. No app in the competition will have this level of warmth.

5
Animated insight delivery

Score ring draws in on load, number counts up with animateFloatAsState. Never instant-appear. The animation IS the delight.

6
Skeleton shimmer on morning card

Show content shape while LLM generates insight. Never blank screen. Synchronized shimmer across whole card, not spinning indicator.

7
First-run empty state with personality

"Данных пока нет. Носи телефон с собой сегодня, и завтра утром появится первый прогноз." + Lottie animation. Guides + delights, doesn't abandon.

8
Bottom nav: 3 tabs maximum

Today / История / Настройки. Fewer tabs = more focused = more UX Award signals. Today opens to morning forecast. Evening: Today shows check-in prompt.

The Character Opportunity (High Impact)

Focus Friend won Play 2025 specifically because of an animated bean character. Wysa won users specifically because a penguin mascot reduced stigma. Consider: a small illustrated/animated element that reacts to the day's data state.

Implementation: Not a humanoid (uncanny valley risk). An abstract animated shape — ring, orb, cloud — that breathes differently based on readiness score. "Calm day" = slow pulse. "Active day" = energized bounce. Uses Lottie + state-driven playback speed.

Suggested App Typography Pair

  • Display/Headline: Fraunces (optical serif)For greeting, score, key moments. Expressive at large sizes, readable at small. Not the default Android look — distinctive.
  • Body/UI: DM Sans or OutfitClean, warm, slightly geometric. Good weight range for hierarchy. Pair well with Fraunces without competing.
  • Data/metrics: JetBrains Mono or Roboto MonoNumbers in tabular layout for step counts, sleep hours, screen time. Mono ensures digit alignment.
