# LLM eval & budget-burn — бриф задач

Разрешено потратить остаток бюджета ключа (на 2026-10-30: **~55k из 75k осталось**, цель ~50k за 5 дней ≈ 10k/день). Задачи подобраны так, чтобы спенд был **полезен продукту**, а не просто сожжён.

**Важно:** прогоны идут ключом напрямую, мимо приложения → **не попадают в Calls/DAU / call_log**, ложатся в серый «dev»-сегмент бюджета на странице метрик. Соревновательные метрики остаются чистыми.

**Экономика:** gigachat ~0.19₽/вызов (50k = ~260k вызовов, нереально). Поэтому judge и model-comparison гонять на дорогих моделях (claude/gpt — где качество и есть цель), генерацию — на дешёвых объёмом.

Доступно 104 модели на прокси (`/v1/models`). Для свипа: `gigachat-3-pro` (прод), `gigachat3.5-432b-a28b`, `deepseek-v4-pro`, `claude-sonnet-4.6`, `gpt-5.1`. Judge: `claude-opus-4.6` / `gpt-5.5`.

---

## 1. Промт-свип + LLM-judge ⭐
Все промты × синтетические дни (хороший/средний/тяжёлый + edge) × модели × температуры; judge оценивает: наблюдательный тон (нет советов), галлюцинации (факты не из данных), кэтчи, лимит длины. → лучший промт/модель/темп по каждой фиче.

## 2. Сравнение моделей quality/cost/latency
Те же промты через модели прокси; замер качества (judge) + кост + латентность. → матрица → рекомендация прод-модели (латентность важна: утренний батч таймаутит).

## 3. Аудит всех исторических выходов
Judge по всем реальным выходам (на 30.10: morning 1068 + reviews 1666 + explore 200 = **2934**): утечки советов, галлюцинации, шаблонность, длина. → список дефектов + аргумент Стадии 2 «проверили 100%».

## 4. Генерация синтетических персон/историй
N реалистичных историй (паттерны, edge) — топливо для #1–2 и теста explore (лечит «Хочу ещё → мало данных»).

## 5. R&D новых сигналов/паттернов
LLM брейнштормит кандидатные паттерны из агрегатов → валидируем качество инсайта. Продуктовый moat + разблокировка explore.

## 6. Edge-case / robustness
Вырожденные входы (нет данных, экстремумы, противоречивые чек-ины, разрывы) → промты не ломаются/не галлюцинируют/не советуют. → фиксы.

## 7. Follow-up на масштабе
Длинные цепочки follow-up, скоринг связности/дрейфа. → лимиты глубины + качество.

## 8. Недельные сводки / лендинг-копи
Много вариантов через модели, judge-ранжирование по «продающести». → банк копи.

---

## Реализация
Ядро — **eval-харнесс** (`scratchpad/eval_harness.py`): датасет → прогон {промт×модель×темп} → judge-скоринг → CSV. Закрывает #1–3, крутится фоном. #4–8 — конфиг/скрипты поверх. Результаты сводятся в `internal-docs/dev/EVAL_RESULTS.md`.

Аудит (#3) — отдельный проход: тянет реальные выходы из БД (`morning_messages`/`reviews`/`explore_answers`), judge по каждому.
