# llm-audit — аудит качества LLM-выходов

Проверяет все реальные тексты приложения (утро, разбор дня, недельные, follow-up, инсайты, explore) двумя независимыми judge-моделями: **совет** (нарушение «только наблюдения»), **выдумка** (факт, которого нет в данных), **шаблонность**. Результаты и методология — в `internal-docs/research/compliance/METRICS_INTEGRITY.md` и `LLM_EVAL_TASKS.md`.

## Запуск (без Claude)

```bash
bash tools/llm-audit/run.sh export    # выгрузить тексты + факты с сервера (нужен ssh-алиас companion)
bash tools/llm-audit/run.sh start     # аудит волнами в фоне; можно остановить и продолжить
bash tools/llm-audit/run.sh status    # прогресс
bash tools/llm-audit/run.sh summary   # сводка по категориям и динамика по неделям
bash tools/llm-audit/run.sh stop
```

Нужно: Python 3, `backend/.env` с `LLM_API_KEY` и `LLM_BASE_URL`. Сторонних библиотек нет.

## Как работает

- **Волны:** за волну берётся по 10 случайных текстов из каждой категории (WAVE=…) (категории идут по кругу), поэтому динамику видно уже после первой волны. После каждой волны автоматически пишется сводка в `data/summaries/wave_NN.txt` и строка итога в лог (`run.sh status`). Следующая волна идёт сразу за предыдущей.
- **Judge:** `gpt-5.1` и `claude-sonnet-4.6` (JUDGES=… переопределяет). Каждый оценивает текст по фактам пользователя за 8 дней. Один judge мягкий, другой строгий, поэтому ориентир — консенсус «оба».
- **Возобновление:** каждая оценка пишется в `data/audit_results.jsonl` сразу, повторный `start` пропускает готовое. Сетевые сбои прокси (бывают) добираются следующим проходом.
- **Тихое окно:** с 03:55 до 04:40 МСК аудит ждёт, чтобы не мешать утренней генерации прода на общем прокси.
- **Нагрузка:** по умолчанию 4 потока (`WORKERS=…`). Прокси общий для 50+ ключей и под нагрузкой роняет TLS-соединения.
- **Цена:** около 0.9 ₽ за вызов (два judge на текст ≈ 1.8 ₽); весь корпус (~2900 текстов) ≈ 5–6 тыс. ₽ с ключа.

## Данные и приватность

`data/` в git не попадает (`.gitignore`): там тексты пользователей и их показатели. `user_id` в выгрузку не входит. Факты уходят на модели OpenAI и Anthropic через прокси, а не только на gigachat.

## Известные ограничения

- Judge видят факты только за 8 дней, а «обычные» значения в текстах считаются по всей истории, поэтому часть «выдумок» ложная.
- Данные дня могли дозагрузиться после генерации утреннего текста.
- Показатель «выдумка: любой judge» шумный (≥1 почти везде из-за непроверяемого «после таких дней у тебя обычно…»). Ориентир — консенсус и ручная калибровка спорных случаев.

## Типичные ситуации

| Что случилось | Что делать |
|---|---|
| Первый запуск на новой машине | `export`, затем `start` |
| Нужен свежий срез данных | `stop`, `export`, `start` (готовые оценки сохранятся, новые тексты добавятся) |
| Jan/другие клиенты на том же ключе падают | `stop`, подождать, `start`, либо `WORKERS=2 bash tools/llm-audit/run.sh start` |
| Много ошибок `URLError` в `status` | это прокси: ничего не делать, следующий проход добирает |
| Мак ушёл в сон / перезагрузка | `start` снова, продолжит с места остановки |
| Посмотреть итог | `summary` (ориентир: консенсус «оба», а не «любой judge») |
