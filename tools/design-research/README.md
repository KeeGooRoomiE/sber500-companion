# design-research: исследование иконки и дизайна силами моделей

Автономные агенты на ключе акселератора сами ищут в интернете, осматривают реальные иконки и экраны приложений-ориентиров, строят выводы, затем нейросети рисуют кандидатов, а панель из трёх моделей их оценивает.

## Запуск (без Claude)

```bash
bash tools/design-research/run.sh selftest          # проверка инструментов и моделей, ~5-10 мин
bash tools/design-research/run.sh start             # иконка, затем дизайн (в фоне, Мак не уснёт)
bash tools/design-research/run.sh start icon        # только иконка (или design)
bash tools/design-research/run.sh status            # прогресс
bash tools/design-research/run.sh open icon         # gallery.html + REPORT.md
bash tools/design-research/run.sh stop              # остановить; start продолжит с места остановки
```

Нужно: Python 3, macOS (`sips` для картинок), `backend/.env` с `LLM_API_KEY` и `LLM_BASE_URL`.

## Что происходит

1. **Исследование.** Три агента (`claude-opus-4.8`, `gemini-3.1-pro-preview`, `gpt-5.1`) получают бриф из `briefs/*.md` и три инструмента: `web_search` (DuckDuckGo, запасной Bing), `fetch_page`, `view_image`. Работают независимо, до `MAX_STEPS` шагов. Каждый вызов инструмента пишется в `agent_*.log.jsonl`, осмотренные картинки сохраняются в `refs/`.
2. **Синтез.** `claude-opus-4.8` сводит три отчёта в 6-8 направлений иконки (или рекомендации и концепты для дизайна).
3. **Генерация.** `gemini-3-pro-image-preview` и `gemini-3.1-flash-image-preview` рисуют по 4 варианта на направление. (`gpt-image` этому ключу запрещён.)
4. **Панель.** Три модели оценивают каждого кандидата (читаемость в 48 px, отличие от категории, соответствие бренду, запоминаемость, привлекательность, лучше ли текущей).
5. **Доработка** (иконка): для 6 лучших модель пишет улучшенные промты, снова генерация и оценка.
6. **Отчёт:** `data/<icon|design>/REPORT.md` и `gallery.html` (кандидаты, их 48-px версии, иконки конкурентов, которые агенты реально открыли).

## Лимиты и безопасность

- `SPEND_CAP` (по умолчанию 15000 ₽): считается по приросту спенда ключа в `/key/info` с начала прогона; при превышении этапы останавливаются. Учитывай, что параллельный аудит (`tools/llm-audit`) тоже тратит с этого ключа.
- `MAX_STEPS` (24) и `AGENT_TOKEN_CAP` (1.5 млн токенов промптов на агента): агентный цикл на дорогой модели это ровно то, что сожгло 19.5k в инциденте (`internal-docs/dev/LLM_SPEND_GUARDRAILS.md`).
- Агенты могут только читать публичные страницы: нет записи, нет доступа к внутренним адресам (`localhost`, одиночные имена, `.local`/`.lan`, приватные IP). Ключ в контекст моделей не попадает. Содержимое страниц считается данными, а не инструкциями.
- Модели видят описание продукта, текущую иконку и скриншоты экранов. Кастдев-цитаты с именами не отправляются.
- `data/` в git не попадает.

## Что результат значит и чем не является

Оценки выставили языковые модели. У них нет данных о реальной кликабельности и конверсии, поэтому ранжирование это экспертное мнение, а не измерение. Нейросетевые картинки склонны выглядеть лучше, чем работают в 48 px. Реальную проверку даёт показ 2-3 финалистов респондентам или A/B листинга в сторе.

## Известные особенности

- На Маке с VPN/прокси-клиентом DNS отдаёт публичным сайтам адреса `198.18.0.0/15` (fake-IP): диапазон явно разрешён в `check_url`.
- Страницы RuStore часто рендерятся скриптами, текста в HTML нет: агенты находят иконки через поиск и Google Play.
- Прокси иногда роняет соединения: все вызовы повторяются, этапы возобновляемы.
